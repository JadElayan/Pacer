# Pacer

Pacer is a live classroom whiteboard with student-controlled explanations and anonymous class insights. The Teaching dashboard hosts and resumes lectures. The Learning dashboard joins meetings and reviews saved lessons. Signed-out visitors first see an onboarding page that explains what Pacer does for students and teachers, with Google sign-in or Continue as guest.

## Start here

Use Node.js 22 and npm. Run `npm ci` and `npm run dev`, then open http://localhost:3000. On Windows PowerShell, use `npm.cmd` if script execution is blocked. Copy `.env.example` to `.env.local` for optional integrations. `npm run lint` checks TypeScript and `npm run build` checks the production build.

| Configuration | Behavior |
| --- | --- |
| No Supabase configuration | Guest rooms sync between tabs in the same browser. |
| `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Enables Supabase Realtime for live rooms across devices. Use the public anon key. |
| `NEXT_PUBLIC_AUTH_ENABLED=1` | Enables Google sign-in after OAuth is configured. See [account setup](AUTH_SETUP.md). |
| `ANTHROPIC_API_KEY` and optional `ANTHROPIC_MODEL` | Enables server-side AI. Without a key, replies use labeled demo content. |
| Optional `ANTHROPIC_LIGHT_MODEL` | A cheaper model (for example `claude-haiku-5-5`) for topic titles, practice questions and teacher tips. Unset, everything uses `ANTHROPIC_MODEL`. |
| Optional `AI_UNITS_PER_DEVICE_DAY`, `AI_UNITS_PER_ROOM_DAY`, `AI_UNITS_GLOBAL_DAY` | Daily AI budgets in token units (defaults 600,000 / 4,000,000 / 40,000,000). See [AI cost and abuse controls](docs/ARCHITECTURE.md#ai-cost-and-abuse-controls). |
| `NEXT_PUBLIC_TEACHER_STORAGE_ENABLED=1` | Enables optional teacher room and slide backups. Requires the storage migration. |

## Current features

- Teachers can rename live lectures, edit and format text in place, add equations (powers and fractions format while typing: `x^2`, `a/b`), ink, shapes and sticky notes in any color, and templates, and pan or zoom the board. Selecting a sticky note or shape shows a floating toolbar (Miro style); shapes and notes resize to any width and height (corners and edges, Shift keeps proportions). Every color picker uses the same "liquid" swatches that flow from one color to the next. Connectors snap to objects and can be reattached. Archived boards and saved lectures preserve teaching materials. Continuing a saved lecture starts a new meeting. Saved lectures can be removed from the Teaching dashboard. Guests keep lectures only in their browser, and choosing Continue as guest starts with an empty dashboard.
- A row above the board holds the lecture's topics (title and short description, editable), a **Slides / Board / Split** switch, and Start new topic / Clear pen / Clear board. A first topic exists as soon as the room opens. Split shows the slide and the whiteboard side by side, or stacked when space is narrow or a student's notes are open; a handle resizes them and either arrangement can be pinned. On phones it becomes two tabs. Focus mode (F) hides everything but the board. Clearing acts on whatever is on screen (the slide, or the side used last in Split).
- Topics remember the slides shown while they were live. A topic's page shows those slides with the teacher's ink, plus its whiteboard notes. Topics made only of slides are titled from the slide text.
- The post-class package (recap, practice questions, catch-up note) is generated only when the teacher presses Generate, and is kept for the room so reopening it doesn't use the AI again.
- Students can follow the teacher or browse independently, ask questions about notes or a snip, catch up, and answer check-ins. Signed-in students can save lessons and learning progress. The lesson list stays short: compact rows that open a summary of what was covered plus a preview (with Open lesson, Rejoin and Remove), the latest four with Show all, Today / This week / Earlier groups, search once there are more than six, empty classes hidden, untitled lectures named after their first topic, and Remove from my lessons.
- Classes: signed-in teachers create classes on the Teaching dashboard (name, subject, color) and share a 6-character code or a `/join/<code>` link. **Start class** (or picking a class on Start Meeting) files the meeting under that class and shows students "Class is live · Join". Signed-in students join with the code, the link, or automatically from a class meeting. The Learning dashboard groups lessons **By class** (a teacher-made class, else the same teacher and subject), with **All lessons** as the other view. Needs `supabase/classes.sql`; without it, lessons still group by teacher and subject.
- Share with class: in the post-class package, **Share with class** sends students the recap, key points, practice questions and catch-up note (never the teacher note). Students in the meeting get a banner and a Class recap sheet; it is saved with their lesson, shown in the dashboard preview and on the lesson page. **Share the new version** updates it after Regenerate, and **Stop sharing** removes it.
- Guided review (saved lessons): a panel walks through each slide (title-only divider slides skipped), then each topic, moving the page along. Slide text is split into a title and points, even when a PDF runs it together. Overview slides let students tap the parts that feel unclear; slides with questions show the first one to try; others ask for it in their own words. Got it or Still unsure (and tapped parts) feed the study plan. Explain this and Quiz me use AI only when clicked. Turn it off with **Guided review** in Settings.
- Your progress (Learning dashboard, private to the student) is built around a short **study plan** for one topic (the most-missed one, or the newest review mark, or any topic the student picks): re-read the notes where it was taught, retry the missed check-ins (graded on the device, no AI), and try a practice question. **Explain it to me** and the practice question use AI only when clicked. Finishing a plan offers the next topic. Around it: a this-week line (classes, check-ins right, weeks in a row), topics by subject marked Strong, Mixed or Needs work (click one to study it), **How it felt** (topics that went from I'm lost to Got it), and **To revisit** with Study this, Open the lesson and Got it now. Older review marks are matched to their saved lesson so they link and show a real name.
- The **Share** button works like Zoom Whiteboard sharing: the teacher sets students to View only or Can add notes, and signed-in students can then add sticky notes to the board and edit their own. Private annotation data uses separate per-account storage and is excluded from shared room updates. Students who aren't signed in can still annotate the board privately; their annotations stay on their device.
- Teachers can upload PDFs, images, and plain text notes. Export slides and documents to PDF to preserve their layout. Production uploads require teacher sign-in, teacher storage, and the slide image migrations; development can use local disk and supports Office imports when LibreOffice is installed.
- Students can write private notes in each classroom and save them in the current browser, including when the board is view only. They can hide or show the notebook, copy any part of a slide or board into their notes with **Clip** (no AI, trimmed to just what was boxed), and switch the notebook between **Type** and **Write**, two separate views of each topic: typed notes, or the handwriting page (clips show in both). Write gives each topic a lined page for a pen or finger and lets students write over clips. Pens draw with pressure, and a resting palm leaves no marks. Clips are pictures placed anywhere on a topic's notes, in Type and Write mode: drag one to move it, double-click a picture clip to open it large and write over it (pen colors, highlighter, eraser, undo; Done or Esc closes), resize it freely from the corner (Shift keeps its shape) or one way from the right or bottom edge, and the picture fills its box. Arrow keys move a selected clip and Delete removes it. Saved answers are blocks: drag the ⋮⋮ handle, use Alt+↑ / Alt+↓, or the block menu (Move to another topic, Remove). Type and Write are also available when reviewing a saved lesson. Saved AI explanations and catch-ups arrive as labelled cards that can be edited, hidden, moved or turned into ordinary notes.
- **Catch me up** lists the topics without using AI; a student presses Explain to ask for one.
- Teachers can pause student AI at any time, and it pauses itself while a check-in is open. The AI route also refuses paused rooms (needs [room_ai_pause.sql](supabase/room_ai_pause.sql)). The teacher sees how many tries were blocked, without names.
- After a deck upload, AI reads it once and suggests check-ins. Questions written on a slide (like "1. What is the area under the curve?") are always suggested for that slide too, with no AI. A suggestion shows only while its own slide is on screen. Answer keys come only from the slides, stay visible to the teacher while the question is open, and slides that would give the answer away can be hidden until presented. In the Pages list, arrow keys move through slides.
- AI spending is controlled: low effort for short answers, no thinking for titles, answers shared between students and cached, fewer automatic calls, smaller images, and daily token budgets per device, class and site with abuse logging (see [AI cost and abuse controls](docs/ARCHITECTURE.md#ai-cost-and-abuse-controls)).
- Pacer can be installed to a tablet or phone home screen, with larger touch targets and a portrait layout. On phones the classroom keeps the board in front: a one-line header whose ⋯ menu opens as a bottom sheet, and for teachers a floating tool bar that slides sideways. Tap the active pen or highlighter again for colors and widths. On tablets the header folds extra tools into ⋯ only when they don't fit on one row.
- Layout switches, board items, tool rails, slide thumbnails and panels are animated; everything respects reduced-motion settings.

## Deployment and database

Deploy this Next.js repository to Vercel and configure the environment variables above for the target environment. The public Supabase settings are read at build time. Add the deployment URL to Google sign-in redirects as described in [account setup](AUTH_SETUP.md). Keep the Anthropic key in server-side environment settings.

Supabase SQL is applied separately from Git and Vercel. For a new environment, configure the existing account tables described in the account setup, then apply [student lessons](supabase/student_lessons.sql), [saved teacher lectures](supabase/saved_teacher_lectures.sql), [teacher storage](supabase/pacer_cloud_storage.sql), [transparent slide support](supabase/transparent_slide_images.sql), and [board collaboration](supabase/board_collaboration.sql) with its [annotation owner access](supabase/annotation_owner_access.sql) follow-up, [room keys](supabase/room_keys.sql), and [AI pause](supabase/room_ai_pause.sql). Confirm which scripts are already applied before setting up an existing project: [supabase/README.md](supabase/README.md) lists every script in order with its status, and [check_installed.sql](supabase/check_installed.sql) reports what a project has.

## Verification and open work

The textbox workflow was verified locally for range formatting, resize, undo/redo, reload, and reopening a saved lecture. Connector snapping, reconnection at 125% zoom, deletion, undo/redo, and reload were also verified locally.

After applying the collaboration migration, verify with a signed-in teacher and two distinct student accounts. Check that disabling contributions blocks further writes while preserving drafts, and that private annotations reopen for their owner and are inaccessible to other accounts. Hosted multi-account verification is pending. Live classroom traffic uses a public Realtime channel. After [room keys](supabase/room_keys.sql) is applied, each meeting registers a public signing key when it starts, and students accept board updates and check-in grades only when the browser that created the meeting signed them. Without that migration, rooms stay unlocked and the teacher sees a notice. Student questions and answers on the channel are still unauthenticated, and a teacher can only sign from the browser that created the meeting.

## Launch readiness

Rate limits on the AI route, anonymous usage metrics, a waitlist, privacy/terms/data-request pages and the post-class package are in this repository. See [launch checklist](docs/LAUNCH_CHECKLIST.md) (do this first), [outreach kit](docs/OUTREACH_KIT.md), [pricing](docs/PRICING.md) and [acquisition readiness](docs/ACQUISITION_READINESS.md). Run `supabase/launch_readiness.sql` once in the Supabase SQL editor. `npm test`, `npm run test:e2e` and `npm run test:a11y` run the unit, smoke and accessibility checks; CI runs all of them on every pull request. Optional variables: `NEXT_PUBLIC_CONTACT_EMAIL`, `AI_LIMIT_PER_MINUTE`, `AI_LIMIT_PER_DAY`, `AI_GLOBAL_DAILY_CAP`, and the token budgets above. Run `supabase/ai_token_budget.sql` so budgets are shared across server instances.
